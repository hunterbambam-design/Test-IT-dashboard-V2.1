Why this exists

I'm studying for the Google IT Support Professional Certificate and building toward an entry-level IT role. I built this dashboard to practice the concepts hands-on instead of just reading about them — networking math, identity provisioning, ticket triage, and security fundamentals, all in one place I could keep iterating on.

What I'd do differently for production

This is a portfolio demo, not production software, and it shows in a few deliberate places: no backend, no auth, no real API calls anywhere. If I were building the real version of any one of these tools, I'd add server-side validation instead of trusting client input, real authentication before touching identity data, rate limiting on anything resembling the phishing/security tools, and proper logging instead of a browser's local storage. I kept this version client-side on purpose — it's honest about being a demo, and it means anyone can try it with zero setup.

Known Limitations

  • Ticket triage is simple keyword matching, not a trained ML classifier — it won't catch phrasing it wasn't written for
  • Network diagnostics and the firewall alert are fully simulated — no real requests are made anywhere in this app
  • The Subnet Calculator, RAID Calculator, and Phishing Header Analyzer are the exceptions: those do real math/parsing on whatever you enter, not canned output
  • The Phishing Header Analyzer checks a handful of common signals (SPF/DKIM/DMARC, domain mismatches) — it's a demonstration of the concept, not a substitute for a real email security gateway
  • The Decision Tree covers 4 common issues with a fixed set of branches — it's illustrative, not an exhaustive troubleshooting KB
  • Generated scripts and CSVs (AD / Entra ID / Linux / bulk import) are syntactically realistic templates for demo purposes — always review before running anything like this against a real system
  • All data lives in your browser's local storage only — clearing site data or switching browsers resets everything except an exported JSON snapshot
